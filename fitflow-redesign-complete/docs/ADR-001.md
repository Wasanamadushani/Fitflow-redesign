# ADR-001: Adopt a React-Native-led, service-oriented stack

## Status

Accepted

## Context

FitFlow needs to deliver AI-powered personalization, real-time social features and computer-vision nutrition logging across iOS, Android and web quickly, while meeting strong security and privacy expectations and remaining affordable for a mid-sized team.

## Decision

Use:

- React Native + React Native Web for the client
- Node.js/NestJS for core backend services
- Python/FastAPI for AI/ML workloads
- PostgreSQL as the system of record
- Firebase Firestore/Realtime Database for real-time social features
- Firebase Authentication for authentication
- Redis for caching
- Firebase Cloud Messaging for push notifications

## Alternatives Considered

- Flutter + Python/FastAPI + PostgreSQL + Auth0
- Kotlin Multiplatform + Go + DynamoDB + AWS Cognito

## Rationale

The selected stack provides strong cross-platform reuse, rapid development, a large ecosystem, real-time integration and a dedicated Python environment for AI/ML.

## Positive Consequences

- Shared frontend development across platforms
- Strong AI/ML ecosystem through FastAPI
- Low incremental cost for managed real-time infrastructure
- Easier hiring and development with TypeScript
- Separation of AI workloads from the core API

## Trade-offs

- Two backend languages introduce operational overhead
- Firebase introduces some vendor dependency for the real-time layer
- Native modules may still be required for certain device-specific AI/vision capabilities

## Security Note

Technology selection alone does not establish GDPR, CCPA or HIPAA compliance. Compliance depends on architecture, configuration, contracts, data handling, organizational controls and applicable legal requirements.
